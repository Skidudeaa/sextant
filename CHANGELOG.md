## 2026-07-15 — Decision-grade coherence telemetry (docs/032)

Failed report analyses and failed active-window file-touch observations are explicit integrity stops rather than silent missing denominators or clean negative outcomes; `unclear` reviews do not satisfy the factual-adjudication floor, and mutable evidence fingerprints remain in review samples without fragmenting semantic incident identity. Telemetry rotation and experiment state share an immutable-contender ticket mutex, eliminating fixed-path stale-lock takeover races; retention cleanup owns each candidate state lock before deletion and safely ages orphan sidecars.

Phase F now emits schema-v1 lifecycle attempts and canonical report analysis/delivery joins, preserving the denominators needed to judge spawn/return reliability, report delivery, latency, finding incidence, and factual safety. `sextant telemetry --coherence-scorecard [--days N] [--json]` applies conservative seven-day/volume, Wilson-lower-bound, boundary/incident/finding resolution, per-lane latency, and manual-review gates; retries collapse by task/child identity, while hard failures and orphan returns remain visible. `sextant telemetry --review <incidentId> --verdict <verdict> --reviewed-findings N` records one of `accurate_useful`, `accurate_noise`, `false_fact`, or `unclear`, with confirmed false facts forcing investigation. `coherenceHoldbackPct:50` enables a deterministic task-level 50/50 experiment on parent-visible `parent_prompt` and `tool_return` reports: exact overlap rows alone are withheld, changed/invalidated claim retractions always pass, and the first eligible opportunity per task is observed for at most eight parent `Read`/`Edit`/`Write`/`MultiEdit`/`NotebookEdit` calls, 30 minutes, or the next prompt. Child-spawn overlap context is not experimental; child actions and Bash/script mutations are unobserved, so treatment-induced tool/delegation shifts can bias the behavioral proxy. Exact-window enrollment/closure/compliance gates prevent attrition from masquerading as a result; pilot interpretation starts at 40 tasks/arm and the first credible behavioral read requires 150/arm. Telemetry is mode `0600`, uses token-owned rotation at 8 MiB, and keeps one prior generation. Per-session experiment JSON has a seven-day TTL and a 2,048-state-file soft cap; garbage collection removes only inactive state and protects current, locked, or live windows. The pre-change current+rotated baseline contained zero Phase-F events, so the initial status is `DORMANT`, not a negative result. The experiment can establish a causal shift in observed parent file-tool behavior; conflict reduction, task success, and user outcome remain `NOT_MEASURED`.

## 2026-07-15 — Multi-agent coherence (Phase F of the context-coherence arc, docs/031)

Sextant can now record exact bounded context actually delivered to a parent, plus context persisted by PreToolUse as a prepared child-spawn rewrite, as immutable boundary snapshots; re-check each recorded agent's claims against the repository now; and surface exact overlap among parent-visible role rows and child-visible neutral paths. `spawn_prepared` deliberately does not claim that stdout succeeded, the Agent tool accepted the rewrite, or the child ran. Reports travel only at proven hook/tool boundaries—the next parent prompt, a new child-spawn rewrite, the matching parent-side Agent/Task return, `sextant_task_status`, and closure—and state facts only: no code locks, ownership, editor attribution, conflict verdict, or running-child push channel. Telemetry records generation/return/report/skip volume, not behavioral benefit, and retained Phase-F events disappear from text/JSON/tail views when the gate is off. The correctness pass serializes exact spawn/tombstone/return transitions under a per-agent integrity lock, uses immutable contention poison so a timed-out registration cannot expose an older preparation, bounds reports/storage independently, preserves task-long edit evidence under a token-owned capsule lock, makes filesystem session keys collision-safe, hashes complete rewritten inputs for retry identity, makes claim invalidation conservative across Swift/CommonJS/TypeScript forms with descriptor-stable bounded file snapshots, and folds closure changes to net unique per-path facts. ## 2026-07-15 — Structural Delta + Closure (Phase D of the context-coherence arc, docs/029)

After an edit, sextant now answers "what did this change in the repository's observable structure?" and produces a factual task-closure report. `lib/structural-delta.js:computeStructuralDelta` diffs a file's post-edit extraction against the graph's STORED extraction — the graph is the pre-image at PostToolUse time (the watcher hasn't re-indexed yet) — yielding exports/imports added/removed with no new extraction and no LLM. The PostToolUse hook (Lane 3, capsule-gated) records it into the capsule's `touchedRegions` and emits `structure.delta`. `sextant closure` / MCP `sextant_closure` (**9 tools now**) assemble the **evidence-closure report** from the capsule + claim ledger + touchedRegions + the session's observed-file set: changed files (structure), context consistency (served claims re-checked: unchanged/re-derived/invalidated), directly-connected witnesses observed vs NOT observed, affected surfaces inspected vs NOT inspected, and unknowns — ending *"states the evidence that EXISTS and the connected surfaces NOT observed; does not assert the change is correct, complete, or safe to merge."* (`capsuleEnabled` moved to `lib/capsule.js`, shared so B/C/D turn on together.) Rides capsule mode (default-off); closure is read-only and always available. Gates: unit 1003/1003 (+`test/closure.test.js`), self-eval stable (21/21, MRR 0.900 / nDCG 0.920).

## 2026-07-15 — Claim Ledger (Phase C of the context-coherence arc, docs/028)

Every structural fact sextant injects now becomes an addressable **claim** (`lib/claims.js`): a typed assertion `{subject, predicate, provenance, fileHash, servedAt}` where provenance is the epistemic firewall — `direct` (AST/graph def), `heuristic` (path_match), `live_text` (a zoekt match, not structural) — never conflated. Served claims persist in the per-session capsule (the Phase-B seam). On the next hook event, `diffClaims` re-checks each prior served claim against the current file: a moved symbol → **CHANGED** with a re-derived span (`locateSymbolRegion` def-form regex → scope-finder), a vanished symbol → **INVALIDATED**, a removed file → **INVALIDATED**. When anything moved, a facts-only `<sextant-context-delta>` block is prepended to the retrieval block (folded into the dedupe hash so a retraction can't be deduped away) — **cache coherence for agent context**: the agent holds a cached subset of repo claims and sextant retracts the stale ones. Runs on content-stale turns too (the diff is disk-based and RETRACTS rather than asserts, so it's honest exactly when files changed); claims are minted only on fresh capsule turns so the last good orientation stays the baseline. Rides on capsule mode (default-off; Phase F now mirrors actually served baselines into immutable per-agent snapshots, while deltas still land only at the next eligible hook). Telemetry: `claim.served`, `contextdelta.emitted`; `sextant telemetry` renders a Claim-ledger section. Gates: unit 997/997 (+`test/claims.test.js`), self-eval byte-identical (21/21, MRR 0.900 / nDCG 0.920 / +0.012). Verified: a moved served symbol produced `CHANGED … span L1–3 → L3–5`.

## 2026-07-10 — root-sanity guard + zoekt scope/circuit-breaker (the 101 GB home-dir incident)

Field incident: a Claude Code session launched from a user's macOS home directory made the hooks adopt `/Users/<name>` as a project root; the auto-started watcher then fed the whole home dir to `zoekt-index` (whose only default exclusions are `.git/.hg/.svn`) every ~3 minutes, growing a **101 GB** search index at `.planning/intel/zoekt/index` — and regrowing it after manual deletion (25 GiB within hours), with orphaned watchers accumulating. Four fixes, all shipped together:

1. **Root-sanity guard** (`lib/root-guard.js`): home dir / filesystem root / home's parent are refused everywhere (even with project markers); hooks and the watcher — the surfaces that adopt `cwd` automatically — additionally require a project marker (`.git`, manifest, `.codebase-intel.json`, or existing `.planning/intel`). Refused hooks exit before `intel.init` (zero state created; SessionStart emits a one-line honest-absence note); `sextant init` is guarded hard because running it in `$HOME` wires hooks into the GLOBAL `~/.claude/settings.json`. Overrides: `--allow-unsafe-root` / `SEXTANT_ALLOW_UNSAFE_ROOT=1` / `"allowUnsafeRoot": true`.
2. **Zoekt build scoping** (`lib/zoekt-scope.js`): the non-git `zoekt-index` path now passes `-ignore_dirs` (node_modules, `.planning` — the index no longer indexes itself — vendored/build/cache dirs, and user-machine dirs like `Library`) and runs an early-exit corpus pre-check (default 512 MiB, `zoektMaxCorpusBytes`) that refuses to index BEFORE a shard is written.
3. **Index-size circuit breaker**: at trigger time and after each run, an index dir past the cap (default 2 GiB, `zoektMaxIndexBytes`) is deleted and the lane disabled via `zoekt/.disabled.json` + `zoekt.disabled` telemetry; `sextant doctor` shows the reason, the current index size vs cap, and the re-enable command (`sextant zoekt index --force`). Search degrades to rg while disabled.
4. **Orphan hygiene**: `*.tmp` shards leaked by interrupted zoekt runs are age-gated deleted at every trigger; a stuck-but-alive previous indexer (>10 min) is identity-verified (`ps` command contains "zoekt") and SIGKILLed instead of being run alongside — overlapping full rebuilds were a growth compounder.

Verified live: scoped `buildIndex` on a fixture with `node_modules` indexes the source and zero vendored content; cap-trip → disabled marker → `--force` re-enable round-trips. Gates: unit 919/919 (+33 new in `test/root-guard.test.js`, `test/zoekt-scope.test.js`), integration green, self-eval byte-identical (21/21, MRR 0.900 / nDCG 0.920 / lift +0.012).

## 2026-07-01 — blast-radius lane: action-time injection after edits (docs/016 Sprint 1)

Sextant's first ACTION-TIME injection: after the agent edits a file, the PostToolUse hook may emit one factual note — the file's dependents not yet touched this session plus its top git co-change partners — via the `hookSpecificOutput.additionalContext` JSON envelope. This targets the "missed blast radius" orientation-failure class named in the project mission but previously unserved: prompt-time retrieval answers "where is X", not "what breaks if I change X".

Grounded by four recon spikes with pre-registered kill criteria (`docs/016-phase0-recon.md`):
- **R1 field-verified the channel** (Claude Code 2.1.198, marker experiment): plain PostToolUse stdout goes to the debug log ONLY — the long-standing CLAUDE.md caveat claiming it "can reach the transcript/context" was WRONG (now corrected, Visibility Model table updated). The JSON envelope IS injected as a `<system-reminder>` immediately after the tool call.
- **R2 pass-with-filters**: raw co-change top-50 is 40-86% CHANGELOG/docs junk; filtering to indexed source files leaves ~0% junk, and 37% of sextant's own filtered pairs have NO import edge (hub-orchestrated siblings — signal the import graph structurally cannot see). Both v1 requirements shipped: the `isIndexable`+scan-membership pair filter and hub dampening (partner degree > 25 dropped).
- **R3 killed live self-tuning** (88% single-source blocks = no lever for a per-source multiplier; dead-tie simulation; 19/6 lifetime samples on the thin sources; rolling transcript corpus). Fallback shipped: `sextant tune` — REPORTING-ONLY per-source open rates with 95% Wilson intervals and n≥30 prior-eligibility; no scoring weight reads it.
- **R4**: no hook channel to Task/workflow subagents exists (0/200 transcripts) — subagent orientation excluded from this sprint's scope.

Mechanics: `lib/cochange.js` parses `git log -n3000 --name-only --no-merges` at bulk-scan finalize into `cochange_pairs`/`cochange_degree` (wholesale replace, count≥3 floor, 5000-pair cap, NUL pair keys); SCHEMA_VERSION 2→3. Emitter discipline: fan-in ≥ 3 or partner confidence ≥ 0.4 to speak at all; once per (session, file); Reads and repeat edits silent; content-stale graph emits NOTHING (silent absence); freshness's git cost paid only on would-emit turns; never throws. Telemetry: `blastradius.injected` + audit section in `sextant telemetry`. Per-session state at `.planning/intel/.blastradius.<sessionKey>`.

**Self-caused-drift exception — found by the headless gate, not by dogfooding.** In-session emissions "worked" throughout development (sextant's own watcher kept re-stamping scan state), but the headless end-to-end run in a freshly-wired watcher-less repo came back ABSENT: the agent's own edit makes the tree content-stale at exactly the moment the note should fire, so strict freshness suppression killed the lane for its flagship use case. ## 2026-04-30 (later same day) — silent-absence freshness gate at the injection layer

Replaced the elapsed-time "ALERT: INDEX STALE" mechanism with a real-state freshness gate. The previous design checked `hours-since-generated_at` and shipped the full structural body anyway — which (a) cried wolf on idle but unchanged repos, training the LLM to ignore the alert, and (b) still leaked stale numeric fields when the repo *had* changed. The new gate (`lib/freshness.js`, `lib/cli.js applyFreshnessGate`) keys staleness to actual repo state — git HEAD, `git status` fingerprint (filtered to exclude sextant's own `.planning/` writes), scanner version, and graph-schema version — and on stale detection sanitizes the injection by construction: no hotspots, no fan-in numbers, no entry points, no module-type histograms, no health percentages, no value derived from `graph.db`. The minimal stale body retains only fields that derive from the live filesystem and `git` directly (root, branch+HEAD, build-system signals, recent git commits) plus a terse "Structural claims unavailable this turn — rescan {requested|pending|unavailable}" marker that honestly reflects the atomic single-flight rescan state. Async rescan is triggered with `--allow-concurrent --force` and is safe under the mtime-gated cache from earlier today (the watcher's RAM copy gets invalidated on the spawned scan's persist instead of clobbering it). Telemetry (`lib/telemetry.js`) records `freshness.stale_hit` and `freshness.blackout_turn` events to `.planning/intel/telemetry.jsonl` for the future Option-5 adaptive sync/async decision — without this dataset, "telemetry-driven later" becomes hand-waving. 459 unit tests pass (22 new), 5 integration scripts pass, 19/19 eval cases pass. Deliberately deferred: the synchronous-rescan-with-budget path (Option 2) and the per-repo adaptive sync/async chooser (Option 5); both can plug in once telemetry shows when sync is safe.

## 2026-04-30 — mtime-gated `loadDb` cache to fix cross-session staleness

We diagnosed and fixed a cross-session correctness bug in sextant: each Claude Code session's MCP server held a process-global in-memory cache of `graph.db` that was never invalidated, so two concurrent sessions in the same project would silently diverge on `sextant_search` results — one serving its session-start snapshot indefinitely while the watcher updated disk for everyone else. The fix landed as commit `d22fb79`: `loadDb()` now stats `graph.db` on each call and evicts the cache when disk is strictly newer, while `persistDb()` bumps the cached mtime after its atomic rename so writers don't self-invalidate. 446 unit tests + 5 integration scripts + 19/19 eval cases still pass, with eval numbers byte-identical to baseline (the gate is a no-op for retrieval ranking).
